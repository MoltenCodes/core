# Getting started: your first addon in ten minutes

This guide builds a small World of Warcraft addon with MoltenCodes, one step at
a time: a greeting on login, saved settings, an options panel with a slash
command, and a minimap button. Every step is a complete addon you can `/reload`
and try. The last section is a larger addon that does ten common tasks, as a
map of where to go next.

Every code block below is a file the framework's specs load and run on a fake
client (`packages/addonKit/tests/Guide_spec.lua`), so what you copy here works.

You need: a World of Warcraft client (Retail, Mists of Pandaria Classic or
Classic Era), a text editor, and the MoltenCodes bundle. For the language
server, see [AddonKit's README](../packages/addonKit/README.md#language-server).

## 1. The bundle and the files

Download a MoltenCodes release, or build the bundle from a clone of the
repository ([RELEASES.md](RELEASES.md)). Make a folder for the addon in
`Interface/AddOns`, named exactly like the addon, here `FirstAddon`, and copy
the bundle into it as `Libs/MoltenCodes`:

```text
Interface/AddOns/FirstAddon/
├── FirstAddon.toc
├── embeds.xml
├── Core.lua
└── Libs/MoltenCodes/      the bundle
```

`embeds.xml` lists the framework files the addon loads, in order. Generate it
rather than writing it: name the Kits you use and the generator adds what they
need.

```sh
python3 -m tooling.package.embeds addonKit eventKit moduleKit \
  --root 'Libs\MoltenCodes' --out embeds.xml
```

For this first step that is six files:

<!-- fixture: FirstAddon/step1/embeds.xml -->
```xml
<Ui xmlns="http://www.blizzard.com/wow/ui/">
    <!--
        Generated by tooling.package.embeds for: addonKit, eventKit, moduleKit.

        Regenerate it instead of editing it when the selection changes.

```

The `.toc` tells the client what to load:

<!-- fixture: FirstAddon/step1/FirstAddon.toc -->
```toc

embeds.xml
Core.lua
```

## 2. Hello on login

<!-- fixture: FirstAddon/step1/Core.lua -->
```lua
local MC = MoltenCodes:For(...)
local addon = MC:NewAddon()

function addon:OnEnable()
  self.scope.Events:Connect("PLAYER_ENTERING_WORLD", function(event, isInitialLogin)
    if isInitialLogin then
      print("Hello from " .. MC.addonName)
    end
  end)
end
```

What each line does:

- `MoltenCodes:For(...)` gives this addon its facade, `MC`. The client passes
  every addon file its folder name as `...`; pass it on as it is. Every file
  of the addon gets the same `MC`.
- `MC:NewAddon()` is the addon object. Its `OnEnable` runs once the player is
  in the game.
- `self.scope.Events` connects game events for the addon. Everything connected
  through `self.scope` is released when the addon is disabled, so there is no
  clean-up to write.

`/reload` and the greeting prints. If a Kit is missing from `embeds.xml`, the
error names the file to add, at the line that needed it.

## 3. Saved settings

Generate `embeds.xml` again with the database part and SettingsKit:

```sh
python3 -m tooling.package.embeds addonKit addonKit/Database eventKit moduleKit settingsKit \
  --root 'Libs\MoltenCodes' --out embeds.xml
```

and declare the saved variable in the `.toc`:

<!-- fixture: FirstAddon/step2/FirstAddon.toc -->
```toc
## Interface: 120105
## Title: First Addon
## SavedVariables: FirstAddonDB

embeds.xml
Core.lua
```

<!-- fixture: FirstAddon/step2/Core.lua -->
```lua
local MC = MoltenCodes:For(...)
local addon = MC:NewAddon()

local defaults = {
  profile = { greet = true, scale = MC.Range(0.5, 2, 1) },
  global = { logins = 0 },
}

function addon:OnInitialize()
  self.db = MC:Database("FirstAddonDB", defaults)
end

function addon:OnEnable()
  self.scope.Events:Connect("PLAYER_ENTERING_WORLD", function(event, isInitialLogin)
    if isInitialLogin then
      self.db.global.logins = self.db.global.logins + 1
      if self.db.profile.greet then
        print("Hello from " .. MC.addonName .. ", login " .. self.db.global.logins)
      end
    end
  end)
end
```

- `defaults` is a plain table, as with AceDB. `profile` values follow the
  player's chosen profile; `global` values are shared by every character.
- `MC:Database` opens the saved variable with those defaults. It infers a type
  for every field from its default, so `self.db.global.logins = "many"` raises
  at that line instead of saving garbage.
- `MC.Range(0.5, 2, 1)` is a number from 0.5 to 2 that reads 1 until set.
  Defaults give you types; `MC.Range`, `MC.Enum` or a SchemaKit node give you
  bounds.
- `OnInitialize` runs when the client has restored the saved variable.
  `MC:Database` refuses to open earlier, because the client would replace what
  it opened.

## 4. An options panel and a slash command

Generate `embeds.xml` again with both parts (`addonKit/*`), PanelKit and
CommandKit:

```sh
python3 -m tooling.package.embeds 'addonKit/*' commandKit eventKit moduleKit panelKit settingsKit \
  --root 'Libs\MoltenCodes' --out embeds.xml
```

<!-- fixture: FirstAddon/step3/Core.lua -->
```lua
local MC = MoltenCodes:For(...)
local addon = MC:NewAddon()

local defaults = {
  profile = { greet = true, scale = MC.Range(0.5, 2, 1) },
  global = { logins = 0 },
}

function addon:OnInitialize()
  self.db = MC:Database("FirstAddonDB", defaults)
  self.panel = MC:Options({
    type = "group",
    name = "First Addon",
    args = {
      greet = { type = "toggle", name = "Greet me", bind = "profile.greet" },
      scale = {
        type = "range",
        name = "Scale",
        min = 0.5,
        max = 2,
        step = 0.05,
        bind = "profile.scale",
      },
      profiles = MC.OptionsKit:ProfileOptions(self.db),
    },
  }, { db = self.db, slash = "firstaddon" })
end

function addon:OnEnable()
  self.scope.Events:Connect("PLAYER_ENTERING_WORLD", function(event, isInitialLogin)
    if isInitialLogin then
      self.db.global.logins = self.db.global.logins + 1
      if self.db.profile.greet then
        print("Hello from " .. MC.addonName .. ", login " .. self.db.global.logins)
      end
    end
  end)
end
```

- The tree describes the panel: a toggle and a slider, each `bind`-ing a
  database field, and the profile controls from `ProfileOptions`.
- `MC:Options` shows it in Blizzard's settings under AddOns and registers the
  slash command that opens it. If another addon already owns that command, it
  raises and says so.

## 5. A minimap button

Add `launcherKit` to the generator command:

```sh
python3 -m tooling.package.embeds 'addonKit/*' commandKit eventKit launcherKit moduleKit panelKit settingsKit \
  --root 'Libs\MoltenCodes' --out embeds.xml
```

<!-- fixture: FirstAddon/step4/Core.lua -->
```lua
local MC = MoltenCodes:For(...)
local addon = MC:NewAddon()

local defaults = {
  profile = { greet = true, scale = MC.Range(0.5, 2, 1), minimap = MC.LAUNCHER_DEFAULTS },
  global = { logins = 0 },
}

function addon:OnInitialize()
  self.db = MC:Database("FirstAddonDB", defaults)
  self.panel = MC:Options({
    type = "group",
    name = "First Addon",
    args = {
      greet = { type = "toggle", name = "Greet me", bind = "profile.greet" },
      scale = {
        type = "range",
        name = "Scale",
        min = 0.5,
        max = 2,
        step = 0.05,
        bind = "profile.scale",
      },
      profiles = MC.OptionsKit:ProfileOptions(self.db),
    },
  }, { db = self.db, slash = "firstaddon" })
  MC:Launcher({
    icon = "Interface\\Icons\\INV_Misc_Gear_01",
    OnClick = function()
      addon.panel:Open()
    end,
  }, self.db)
end

function addon:OnEnable()
  self.scope.Events:Connect("PLAYER_ENTERING_WORLD", function(event, isInitialLogin)
    if isInitialLogin then
      self.db.global.logins = self.db.global.logins + 1
      if self.db.profile.greet then
        print("Hello from " .. MC.addonName .. ", login " .. self.db.global.logins)
      end
    end
  end)
end
```

- `minimap = MC.LAUNCHER_DEFAULTS` gives the profile the three fields the
  button keeps: its position, and whether it is hidden or locked.
- `MC:Launcher` puts the button on the minimap and keeps it where the player
  drags it, per profile. Clicking it opens the panel.

That is the whole addon: about forty lines.

## 6. Where to go next: ten common tasks

The addon below does the ten things most addons do: an addon object, events, a
repeating and a one-shot timer, a database, an options panel with a slash
command, two locales, a module that can be disabled, addon messages, a hook,
and a minimap button. It is the comparison addon the framework measures itself
against Ace3 with. Its locale files:

<!-- fixture: TenTasks/Locales/enUS.lua -->
```lua
--@T06 the default locale: `true` means the key is its own text
local L = MoltenCodes:For(...).LocaleKit:NewLocale(..., "enUS", { isDefault = true })
L["My Addon"] = true
L["Scale"] = true
L["Five seconds later."] = true
```

<!-- fixture: TenTasks/Locales/deDE.lua -->
```lua
--@T06 a translation, loaded only on a German client
local L = MoltenCodes:For(...).LocaleKit:NewLocale(..., "deDE")
if not L then
  return
end
L["Scale"] = "Skalierung"
```

And `Core.lua`:

<!-- fixture: TenTasks/Core.lua -->
```lua
-- MyAddon: ten common addon tasks with AddonKit. Each `--@Txx` tag marks the
-- task the lines below it belong to.

--@P
local MC = MoltenCodes:For(...)
local L = MC.LocaleKit:GetLocale(MC.addonName)

--@T01 addon with OnInitialize / OnEnable
local addon = MC:NewAddon()

--@T04 database with defaults and profiles: plain defaults, one field refined
local defaults = {
  profile = { scale = MC.Range(0.5, 2, 1), greet = true, minimap = MC.LAUNCHER_DEFAULTS },
  global = { installs = 0 },
}

--@T01
function addon:OnInitialize()
  --@T04
  self.db = MC:Database("MyAddonDB", defaults)
  self.db:OnProfileChanged(function()
    addon:Refresh()
  end)
  self.db.global.installs = self.db.global.installs + 1
  --@T05 options panel in Blizzard's settings, with a slash command
  self.panel = MC:Options({
    type = "group",
    name = L["My Addon"],
    args = {
      scale = {
        type = "range",
        name = L["Scale"],
        min = 0.5,
        max = 2,
        step = 0.05,
        bind = "profile.scale",
      },
      profiles = MC.OptionsKit:ProfileOptions(self.db),
    },
  }, { db = self.db, slash = "myaddon" })
  --@T10 minimap button from a data broker object
  MC:Launcher({
    icon = "Interface\\Icons\\INV_Misc_Gear_01",
    OnClick = function()
      addon.panel:Open()
    end,
  }, self.db)
  --@T01
end

function addon:OnEnable()
  --@T02 register and unregister events
  self.scope.Events:Connect(
    "PLAYER_ENTERING_WORLD",
    function(event, isInitialLogin, isReloadingUi) end
  )
  self.bagUpdates = self.scope.Events:Connect("BAG_UPDATE", function(event, bagID)
    self.bagUpdates:Disconnect()
  end)
  --@T03 a repeating and a one-shot timer
  self.ticker = self.scope.Timers:Every(60, function()
    self:Poll()
  end)
  self.scope.Timers:After(5, function()
    print(L["Five seconds later."])
  end)
  --@T08 send and receive an addon message
  self.scope.Comm:Register("MyAddon", function(prefix, text, distribution, sender) end)
  --@T09 a hook
  self.scope.Hooks:SecureHook("ToggleGameMenu", function()
    self:OnGameMenu()
  end)
  --@T01
end

--@T03
function addon:Poll() end
function addon:StopPolling()
  self.ticker:Cancel()
end

--@T04
function addon:Refresh() end

--@T08
function addon:SendHello()
  self.scope.Comm:Send({ prefix = "MyAddon", text = "hello", distribution = "PARTY" })
end

--@T09
function addon:OnGameMenu() end

--@T07 a module that can be disabled
local bags = MC:NewModule("Bags")
function bags:OnEnable()
  self.scope.Events:Connect("BAG_UPDATE_DELAYED", function()
    self:Rebuild()
  end)
end
function bags:Rebuild() end
function addon:ToggleBags(on)
  if on then
    bags:Enable()
  else
    bags:Disable()
  end
end
```

## When something goes wrong

| You see | Do |
|---|---|
| `MyAddon uses MoltenCodes TimerKit (API 1), which is not loaded` | Add the Kit to the generator command and generate `embeds.xml` again. |
| `MoltenCodes has no Kit or helper named ...; did you mean ...?` | Fix the spelling it suggests. |
| `attempt to call method 'For' (a nil value)` | AddonKit is not loaded: `addonKit` is missing from `embeds.xml`, or `embeds.xml` is missing from the `.toc`. |
| `... opened FirstAddonDB before ADDON_LOADED` | Open the database in `OnInitialize`, not at the top of the file. |
| `... is already used by another addon or a chat command` | Pick another slash command name. |
| `pairs(self.db.profile)` finds nothing | A database view is not a plain table: use `self.db:Pairs(self.db.profile)`. |

[EMBEDDING.md](EMBEDDING.md) has everything about embedding: taint, `/reload`,
load order and more troubleshooting.
