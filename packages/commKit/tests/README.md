`support/CommKitTestEnv.lua` loads Registry, SignalKit, EventKit, TimerKit, SchedulerKit, PoolKit, CodecKit, CommKit and its two parts on the shared fixture (CommKit optionally as an older revision, `Load({ commKitRevision = n })`, revision 10 being the verbatim whole-file copy; `Load({ schedulerKit = false })`, `syncSet = false` and `chatThrottle = false` leave one out, and `withoutSchedulerKit` leaves SchedulerKit out of every `Load` for a whole file), and HookKit, SchemaKit or LifecycleKit on request; CodecKit, HookKit, SchemaKit and LifecycleKit are declared under `optionalDependencies`, so the runner puts them on `LUA_PATH`. LifecycleKit loads after CommKit (`Load({ lifecycleKit = ... })` or `LoadLifecycleKit`), as HookKit can (`LoadHookKitLater`, with its `hooksecurefunc` stub), and `SetClosesAddonScopes` writes `LifecycleKit.CLOSES_ADDON_SCOPES` onto the loaded facade with `rawset`, or removes it to model a LifecycleKit older than 0.6.0. It stubs `C_ChatInfo` with a recorded outbox, every attempt recorded and scripted results; `C_BattleNet.SendGameData` likewise (`QueueBattleNetResults`, `TakeBattleNetOutbox`, `DeliverBattleNet`); `Enum`; `GetFramerate`; `UnitInParty` and `UnitInRaid`; and, for the HookKit chain, `hooksecurefunc`. `Deliver` and `DeliverLogged` emit the chat events through the fixture, and `Loopback` delivers the outbox back as if from a peer, on the channel each message was sent on. A send the bucket pays for leaves inside `Send` (revision 6), so specs that need several messages queued at once call `HoldSends`, which empties the bucket, and `ReleaseSends`, which refills it and advances the clock so the waiting driver sends them.

The fixture's timers fire only when a spec fires them, so the environment wraps `C_Timer` before TimerKit binds it and records when each native timer is due on the fixture clock. `Advance(seconds)` moves the clock, fires every timer that falls due in order and runs the scheduler's frame driver after each; `Advance(0)` runs what is due now, which is how the driver job and SchedulerKit's next-frame timers run. `Frame()` runs one frame (SchedulerKit's frame driver once, or without SchedulerKit every native timer already due, once), and `DriverRuns(CommKit)` counts the armed driver run of either kind.
