# CommKit Tests

Each spec file and what it covers:

| File | Covers |
|---|---|
| `Chunking_spec.lua` | 254 bytes as one chunk, 255 and 256 as two, 502 as two full chunks, 503 and 510 as three, the exact header bytes of each, consecutive stream ids, two-digit chunk numbers past 127, and no forbidden byte in any chunk. |
| `Reassembly_spec.lua` | Single chunks, the logged channel, a loopback of what CommKit sent, no partial delivery, chunks out of order, interleaved streams from one sender, one stream id kept apart across senders and distributions, expiry of a stream with a missing chunk reported once, the timeout counted from the last chunk, chunks for unknown streams, hostile first chunks refused before anything is stored, streams dropped for an out-of-range index, a duplicate, a short middle or an early last chunk, every reassembly bound, a restarted stream id, eviction on `GROUP_ROSTER_UPDATE` (also by the name before the realm), only the first four `CHAT_MSG_ADDON` arguments read, foreign prefixes and unknown control bytes, secret arguments, callback isolation, streams discarded with the last registration, and the expiry timer disarmed when the last stream closes. |
| `Queue_spec.lua` | `tooLarge`, `queueFull` by bytes and by messages, lowering a bound, a queued message failed as `tooLarge` when the reassembly bound is lowered below it, every forbidden byte, `badDistribution` for unknown distributions and missing targets, ignored targets, `closed`, logged sends, `unavailable`, depth per priority, refusal counters, and no handler, job or timer left once idle; priorities: the ALERT, NORMAL, BULK rotation, BULK never starved, round-robin between destinations, chunks interleaved with other destinations, and order inside one destination. |
| `Budget_spec.lua` | The initial bucket, the per-message charge, waiting for the bucket, the zoning mode, the low-frame-rate mode sampled on a timer and never while idle, a chunk above a small burst, limit validation; outside traffic with HookKit loaded (addon, logged and chat messages charged once, CommKit's own sends not charged, debt down to two seconds) and without it; throttling: a throttled pipe set aside while others continue, doubling backoff reset by a success, a long message resumed at the refused chunk, failures named from `Enum` and unnamed results retried, and a send function that raises. |
| `Lifecycle_spec.lua` | Send handles: progress and completion, cancel while queued, mid-send (followed by the abort chunk) and from a progress callback, isolated completion callbacks, `CancelAll`; scopes: `Close` mid-send, shutdown mid-send through LifecycleKit, a scope requested after shutdown, `CloseAddonScopes`; registrations: one client registration per prefix, prefixes the client already holds, `DuplicatePrefix` and every refusal, the 32-registration bound, disconnection, the chat events connected only while needed, and `UnregisterAll`. |
| `SyncSet_spec.lua` | FNV-1a hash vectors of the canonical encoding, insertion-order independence, refused values, clearing, delta replies, acks, removed fields, the reply interval, deliveries and `OnChanged`, requests carrying held hashes, a multi-chunk round trip between two SyncSets, malformed frames, undeclared fields, the peer cache bound, the listener bound, closing; with SchemaKit, schema refusals of received and local values and invalid schemas; without CodecKit or SchemaKit, the refusals at the caller. |
| `Robustness_spec.lua` | The driver: one job at most while completion callbacks chain sends behind a busy destination, the job and ticker disarmed when cancelling empties the queue and when a failed run leaves nothing queued, and the 32-chunk run cap; drop reports: a flood of 100 hostile first chunks reported once at once and once aggregated after a minute, separate senders reported separately, a sender's cancel aborting the receiver's stream silently, mismatched aborts refused, quota refusals reported; sender-side bounds: six concurrent 1000-byte sends across six pipes and two 9000-byte sends delivered under the default bounds, no stream id reused while a stream holding it is in flight, an abort keeping its message's allowance until it leaves, a message that fails mid-send followed by an abort that keeps its allowance, a message above one sender's bound refused; the logged channel's printable header digits and their reassembly, ordinary digits refused on it; `CHANNEL` targets that are not numbers; SyncSet requests refused unless whispered, one queued reply per peer, the 8 KB reply allowance, the reply interval kept when the peer cache is full, and removal winning over a value in one delivery. |
| `Limits_spec.lua` | The `UNBOUNDED` sentinel; `maxRegistrations` default, option on `CreateScope` and `ForAddon`, `UNBOUNDED`, invalid values and a conflicting `ForAddon` refused at the caller; `maxListeners` default, option and `UNBOUNDED`; `maxDropReportSenders`, `maxSyncPeers` (shrinking to a lowered bound) and `maxSyncReplyBytes` honoured; `UNBOUNDED` refused with its reason for every `SetLimits` entry and out-of-range values refused at the caller; set limits, scope bounds and the sentinel identity kept across an in-place upgrade. |
| `Statistics_spec.lua` | Every counter at zero, the counters after a mixed scenario, and a fresh table per call. |
| `Allocation_spec.lua` | `collectgarbage("count")` guards, with the collector stopped, on the single-chunk receive path, a foreign prefix, and the handle and queue queries. |
| `Bootstrap_spec.lua` | Duplicate embedded loading, Registry publication, loading without the optional packages, `securecallfunction` isolation, yielding to a newer revision, an in-place upgrade to revision 2 with a send in flight, an open stream, a registration and a SyncSet, a missing Registry, each missing required package, and an incomplete facade. |
| `ErrorLevels_spec.lua` | Every receiver, argument, option, limit and secret failure, secret constraints and limits included, reported at the caller's own line. |
| `Manifest_spec.lua` | Manifest and runtime API and revision agree, the six required and three optional dependencies, and `optionalDependencies` after the top-level `api`. |

`support/CommKitTestEnv.lua` loads Registry, SignalKit, EventKit, LifecycleKit, TimerKit, SchedulerKit, PoolKit, CodecKit and CommKit on the shared fixture, and HookKit or SchemaKit on request; CodecKit, HookKit and SchemaKit are declared under `optionalDependencies`, so the runner puts them on `LUA_PATH`. It stubs `C_ChatInfo` with a recorded outbox, every attempt recorded and scripted results; `Enum`; `GetFramerate`; `UnitInParty` and `UnitInRaid`; and, for the HookKit chain, `hooksecurefunc`. `Deliver` and `DeliverLogged` emit the chat events through the fixture, and `Loopback` delivers the outbox back as if from a peer, on the channel each message was sent on.

The fixture's timers fire only when a spec fires them, so the environment wraps `C_Timer` before TimerKit binds it and records when each native timer is due on the fixture clock. `Advance(seconds)` moves the clock, fires every timer that falls due in order and runs the scheduler's frame driver after each; `Advance(0)` runs what is due now, which is how the driver job and SchedulerKit's next-frame timers run.
