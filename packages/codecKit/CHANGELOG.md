# Changelog

## 0.3.0 — 2026-11-15

Compression becomes an optional part, as recorded in docs/ROADMAP.md (package O, "codecKit (package O): compression as a part") under ADR 0001. The wire format is unchanged, and with the part loaded every frame, refusal and limit is byte for byte what revision 9 gave.

- **Core and part.** `src/CodecKit.lua` is the core: serialiser, frames, the addon and print channels, the asynchronous variants. `src/parts/CodecKit-Compression.lua` holds the DEFLATE tables, the Huffman codes, the compressor, the inflater and the native compressor (part revision 1, declared under `parts` in the manifest). Resident on the host (Lua 5.1, debug information kept): core 97.4 KB, part 59.3 KB, against 149.4 KB for revision 9; an addon that embeds the core alone holds 52 KB less.
- **Without the part**, `Compress`, `Decompress`, and `Encode`, `EncodeMany` and `EncodeAsync` with `compress = "deflate"`, raise at the caller's line: `CodecKit:Compress is in CodecKit's Compression part, which is not loaded: add codecKit\parts\CodecKit-Compression.lua to embeds.xml after codecKit\CodecKit.lua`. Decoding a compressed frame does not raise: `Decode` and `DecodeMany` return, and `DecodeAsync` calls back with, `false, "compressionUnavailable"`, a new reason.
- Added: `CodecKit:HasPart(name)`.
- State: `parts`, `compression`, `helpers` and `partInterface` (1). An in-place upgrade from revision 9, the whole file, keeps the limits, the sentinel and the pool; with the part loaded nothing changes for a caller, and an asynchronous compression revision 9 scheduled finishes either way (it runs revision 9's own code). A revision 9 copy loaded after a core-only revision 10 yields.
- Implementation revision 10.
- Specs: 165 → 184 (`Parts_spec.lua`; the upgrade specs load a verbatim copy of revision 9, `tests/fixtures/CodecKit-revision9.lua`, as the older copy, and add the part after the core).

## 0.2.2 — 2026-11-15

- Fixed: `validateOptionKeys` and `SetLimits` built their refusal with `tostring(key)`, so a table key with a `__tostring` metamethod ran the caller's code inside CodecKit, which could raise its own error or answer a secret. A key is now named as itself (a string), as written (a number or boolean) or by its type: `CodecKit:Encode options.<table> is not a recognised option`, `CodecKit:SetLimits limits.<table> is not a recognised limit`. A secret key is refused first, before it is used to look the name up, with `options must not have a secret key` or `limits must not have a secret key`. `KeyDescriptions_spec.lua` holds the regression specs; the client suite gains the same check.
- Memory: the one-character byte strings (built on the first encode), the print digit tables (the first print-safe encode or decode) and the DEFLATE symbol and fixed-code tables (the first Lua compression or decompression) are no longer built at load. A session that loads CodecKit and never uses a stage holds about 87 KB less (DEFLATE 59.0 KB, byte text 18.5 KB, print 9.3 KB); the first use pays the build once. `PRINT_ALPHABET` is still built at load.
- Performance: a bounded clean-string cache (at most 256 strings of at most 32 bytes, recorded once, up to about 14 KB held) skips the addon-channel escape scan for repeated keys and values; the escape and forbidden-byte scans use plain searches instead of a character class; encode options are read in one pass with the secret probe read once per call; `writeValue` reads and writes the buffer counters once per value. Host benchmark against AceSerializer-3.0, same session (2026-11-15): encode small, medium and large 1.62, 1.62, 1.24× → 1.37, 1.35, 1.18×; decode 1.24, 1.12, 0.86× → 1.07, 0.95, 0.74×. Decoding is now below AceSerializer's cost for medium and large payloads; encoding is not.
- The secret probe follows the rule every Kit follows: `issecretvalue` is resolved once when the file loads, and looked up at every call only when it was absent then.
- Implementation revision 9. No state field changed: an in-place upgrade from revision 8 keeps the limits, the sentinel and the pool, and frames either revision wrote decode in the other (`Bootstrap_spec.lua`, "upgrades a revision 8 copy in place ...").
- Specs: 149 → 165 (`KeyDescriptions_spec.lua`, `LoadCost_spec.lua`, the upgrade from revision 8).

## 0.2.1 — 2026-11-15

Review fix. The wire format is unchanged, and every frame any revision wrote decodes as before.

- **A secret answer from the client's compressor is no longer used.** Revision 7 measured what `C_EncodingUtil.CompressString` returned with `#` and made it the frame body without asking `issecretvalue`, against the rule that every value the client answers is asked about first; a secret there would have made the whole frame a secret no peer could receive. The answer is now asked about after its type check, and a secret falls back to the Lua compressor like every other answer CodecKit cannot trust. The `Enum.CompressionMethod` and `Enum.CompressionLevel` numbers are asked about too, and a secret one is replaced by the documented number. The client never answers a secret for the non-secret input CodecKit hands it, so no frame a client wrote changes.
- Implementation revision 8. The state layout is unchanged: `Bootstrap_spec.lua` loads a revision 7 copy without the new check, upgrades it in place, keeps the state table, the limits and the pool, and falls back to Lua for a secret answer afterwards.
- Specs: `Native_spec.lua` adds the fallback for a secret answer and the documented numbers for a secret `Enum` field. 149 specs.
- Docs: API.md states revision 8, the secret fallback and the `Enum` fallback, and says exactly which client runs proved the native format (the interoperability tests on Retail 12.1.0 build 69933, 2026-09-25) and which have not run (the four native tests, both Classic flavours). INTERNALS.md records the secret checks and a host fuzz run of 873 zlib raw streams the Lua inflater read without a failure. The README gains the migration table from AceSerializer-3.0 and LibDeflate, and no longer promises a client speed nobody measured. tests/README lists the new specs; the client suite's comments name revision 7 and later.

## 0.2.0 — 2026-11-15

Native compression, as recorded in docs/ROADMAP.md ("codecKit native DEFLATE", core decision 16). The wire format is unchanged: frames are version 1, and every frame any revision wrote decodes as before.

- **The compression stage runs in the client** where `C_EncodingUtil.CompressString` exists: an input of 64 bytes or more is compressed there with `Enum.CompressionMethod.Deflate`, raw DEFLATE, and the result is the frame body. `level` maps 1–3 to `OptimizeForSpeed`, 4–6 to `Default` and 7–9 to `OptimizeForSize`; the method and levels are read from the client's `Enum`, or are the documented numbers when it has none. `EncodeAsync` uses the client's encoder for up to 256 KiB of serialised bytes and the yielding Lua encoder above. A native call that raises, returns nothing, returns anything but a non-empty string or returns more than `maxOutputBytes` falls back to the Lua encoder, so every refusal is the one revision 6 gave. Inputs under 64 bytes stay on the Lua encoder, which allocates nothing for them.
- **Compatibility.** The frames the client's encoder writes decode on every earlier revision, whose inflater reads any raw DEFLATE stream, and on clients without `C_EncodingUtil`. Their bytes differ from the Lua encoder's; without `C_EncodingUtil`, as on the host, every byte is what revision 6 wrote.
- **Inflating stays in Lua on every client.** Deviation from the record, which allowed native inflation behind a 16 KiB input bound once the client showed it refuses bytes after the final DEFLATE block: a frame has no declared length, checksum or end marker of its own, so CodecKit could not tell whether the client's inflater accepted a stream its own inflater refuses with a documented reason. Native inflation waits for a later revision and the client checks `docs/INTERNALS.md` lists.
- No public member is added, and the state layout is unchanged: the client's functions are read at every call and nothing is kept in `_state`. `Bootstrap_spec.lua` loads a revision 6 copy (without the native path), upgrades it in place, keeps the state table, the limits and the pool, and compresses natively afterwards.
- Docs: API.md (the optional facility, which encoder runs, compatibility, the cost of each, the deviation), INTERNALS.md (the native compressor and why inflation stays in Lua), README, tests/README.
- Specs: new `Native_spec.lua` (17 specs) with a `C_EncodingUtil` stand-in in `CodecKitTestEnv`; the revision 6 upgrade in `Bootstrap_spec.lua`. 146 specs.
- Client suite: a `codecKit.native` suite (four tests) checks the native path byte for byte against `CompressString`, round-trips the 50 KB roster through it, logs what `DecompressString` does with trailing bytes and a truncated stream (the condition for native inflation), and times the native encoder on 256 KiB and 1 MiB. Implementation revision 7.

## 0.1.6 — 2026-11-15

The implementation revision line says 6.
- Comments: the header says the same about the addon channel and that only the compression and print stages lease from the pool; a call leases at most three pooled tables, not five.
- `tests/README.md` lists `FastPath_spec.lua` and the revision 4 upgrade spec.
- Implementation revision 6. The state layout is unchanged: `Bootstrap_spec.lua` loads a revision 5 copy, upgrades it in place, keeps the state table and the pool, and compresses stored and Huffman blocks to the frames the older copy wrote.

## 0.1.5 — 2026-09-25

- Performance. Encoding and decoding cost less time and memory, measured with the host benchmark against AceSerializer-3.0 minor 5 with compression off (`python3 -m tooling.bench.run --workload timers --workload codec --rounds 3`, before and after this change, median ns per operation with AceSerializer measured in the same run; other benchmarks ran on the machine at the same time, load average about 6 before and 2.5 after, so compare the ratios and the allocation, which is deterministic):

  | Case | Before | After | AceSerializer (before / after) | Ratio before → after | Allocated before → after (AceSerializer) |
  |---|---:|---:|---:|---|---|
  | `encode-small` | 26,832 | 5,975 | 4,288 / 3,768 | 6.26× → 1.59× | 459 → 138 B (201 B) |
  | `encode-medium` | 364,428 | 153,773 | 109,583 / 101,321 | 3.33× → 1.52× | 11,608 → 4,234 B (4,786 B) |
  | `encode-large` | 1,611,140 | 701,200 | 717,090 / 568,860 | 2.25× → 1.23× | 62,488 → 18,120 B (28,080 B) |
  | `decode-small` | 9,098 | 5,150 | 4,803 / 4,030 | 1.89× → 1.28× | 512 → 512 B (600 B) |
  | `decode-medium` | 189,783 | 131,233 | 144,313 / 116,249 | 1.32× → 1.13× | 20,301 → 20,298 B (20,384 B) |
  | `decode-large` | 761,400 | 550,350 | 747,320 / 609,420 | 1.02× → 0.90× | 71,130 → 71,033 B (71,050 B) |

  CodecKit now allocates less than AceSerializer on every case, decodes the large payload faster, and its output stays smaller (104, 3,152 and 11,736 bytes against 118, 3,675 and 16,311).
- How. A synchronous call no longer leases its work record, fragment buffer and cycle set from the PoolKit pool: it takes one idle work record the file builds once and reuses (a nested call, or the first call after one that raised, builds a fresh one, which then becomes the idle one). The serialiser writes one-character strings from a table built at load instead of batching bytes into `string.char(unpack(...))` runs, appends short strings, small integers, booleans and `nil` inline, reads table contents it knows are present by plain indexing, counts the map part as keys less the array part, and finds cycles on the stack of open tables with `rawequal` instead of in a set keyed by table, which Lua kept rehashing as distinct tables came and went. An uncompressed `Encode` writes the frame header as the first fragment and escapes for the addon channel while it writes, so the frame is the only string built. The reader reads one-byte varint values inline and reads a binary frame, or an addon frame with nothing to unescape, in place instead of copying the body out; an addon frame with escapes is unescaped from byte 3 of the frame without a separate copy. The compression and print stages keep leasing their sinks from the pool. `docs/INTERNALS.md` describes the work record, the writer and the in-place reader.
- The wire format is unchanged, byte for byte: every frame is what revision 4 wrote, every frame revision 4 wrote decodes as before, and every refusal returns the same reason. During the change, 3000 random values under six option sets, their argument-list and `Serialize` forms, and 5000 refusal and malformed-input cases (limits, cycles, unsupported types, truncations, byte substitutions, random text) gave identical output from revisions 4 and 5. `docs/API.md` states what serialising and decoding allocate now.
- What remains against AceSerializer is what CodecKit promises and AceSerializer does not: the secret probe before every value, the `maxValues`, `maxStringLength`, `maxDepth` and `maxOutputBytes` checks after every value, cycle detection, the exact IEEE-754 bytes of every non-integer, argument and option validation, and on decode the header and flags check, the bounds check of every byte and count, and the duplicate-key and `nil`-value refusals. Each is a comparison or a table read per value; together they are most of the remaining time.
- Implementation revision 5. The state layout is unchanged: `Bootstrap_spec.lua` loads a revision 4 copy, upgrades it in place, keeps the state table, the limits and the pool, and writes the frame the older copy wrote.
- Specs: new `FastPath_spec.lua` (230 golden frames revision 4 wrote, for 38 payloads under six option sets and for two argument lists, encoded byte for byte and decoded back; an independent reference writer against `Serialize` and the none, addon and print frames of 400 random values; a payload of many thousand fragments; the in-place frame decoder against the staged decoders over every truncation and eight byte substitutions per position; no reference to encoded strings kept after a call; a call nested through the secret probe; recovery after a probe raised mid-call; a stage output folded into chunks past 1 MiB; malformed argument lists; the stage limits on a body read in place; cycles only on the open path; `maxDepth` exactly on both sides); `Allocation_spec.lua` adds encoding a medium payload within 1.5 times its output, decoding an unescaped addon frame without copying it, `Serialize` and `Deserialize` of a scalar allocating nothing, and encoding allocation-free again after a call raised mid-way and after an in-place upgrade from revision 4. 128 specs.

## 0.1.4 — 2026-09-25

- The serialiser writes every NaN as the canonical quiet NaN `06 7F F8 00 00 00 00 00 00`, as `docs/API.md` promises. Revision 3 derived the sign bit with an ordered comparison before it recognised NaN, and on Retail 12.1.0 b69933 (measured 2026-09-25 by the real-client suite) that comparison answered "negative" for `0 / 0`, so the client wrote `06 FF F8 ...`. NaN is now recognised first with `value ~= value` and written without looking at its sign or payload. The value reaching the writer has already been refused if it is a secret. Decoding is unchanged, and a sign-bit NaN written by revision 3 still decodes to NaN.
- Implementation revision 4. The state layout is unchanged: `Bootstrap_spec.lua` loads a revision 3 copy and upgrades it in place, keeping the state table, the limits and the pool, and the upgraded copy writes the canonical NaN.
- `CodecKitTestEnv.LoadPatched` loads the source with one piece of text replaced; `Serialize_spec.lua` uses it to model the client's sign test, which stock Lua cannot reproduce.
- 110 specs.

## 0.1.0 — 2026-09-23

First release: CodecKit API generation 1, implementation revision 1, wire format version 1 (`CodecKit.FORMAT_VERSION`). Requires Registry API 2 and PoolKit API 1; SchedulerKit API 1 is optional and found with `Registry:Find` by the asynchronous methods.

- **Frames.** A version byte and a stage-flags byte (serialised, deflate, addon, print; four reserved bits), then the body. `Encode(value, options)` and `Decode(text, options)` compose the stages; the decoder reads the stages from the header, refuses an unknown version with `"unsupportedVersion"`, and a `channel` decode option refuses a frame made for another channel with `"channelMismatch"`.
- **Serialiser.** One type byte per value: varint integers up to 2^53, the exact IEEE-754 binary64 bit pattern for every other number (infinities, NaN, −0 and subnormal numbers included), length-prefixed raw strings, array, map and mixed table layouts, and an argument-list type for `EncodeMany`/`DecodeMany` (at most `maxListValues` entries on both sides). Cycles are refused with `"cycle"`; functions, userdata and threads with `"unsupportedType"`; metatables are ignored.
- **Compression.** Raw DEFLATE (RFC 1951) in pure Lua, interoperating with zlib in both directions: LZ77 over exact three-byte hash chains with greedy (levels 1–3) or lazy (levels 4–9) matching, then per block the cheapest of stored, fixed and dynamic Huffman with length-limited codes. Levels 8 and 9 cap their hash chains at 192 and 256 candidates, keeping level 9 within about three times level 6 on low-entropy input. Inputs under 64 bytes skip matching and become one literal or stored block without allocating. The inflater reads all three block types from any encoder.
- **Channels.** The addon channel escapes five bytes behind `0xFF`; the print channel is base 85 over an 85-character alphabet without quotes, backslash, pipe, braces, percent and slash, published as `PRINT_ALPHABET`, and ignores whitespace on decode, before the frame included.
- **Stage methods.** `Serialize`, `Deserialize`, `Compress`, `Decompress`, `EncodeForAddon`, `DecodeForAddon`, `EncodeForPrint` and `DecodeForPrint`.
- **Decoding never raises on malformed input.** Every failure is `false` and a reason from a fixed vocabulary of 22 (21 returned by the synchronous methods, plus `"secret"`, which only reaches an `EncodeAsync` callback). `docs/API.md` defines the well-formed input a lenient reader accepts, and warns that encoded bytes are not a content hash.
- **Limits.** `SetLimits` and `GetLimits` over `maxDepth` (16, ceiling 128), `maxValues` (65536), `maxStringLength` (65536), `maxOutputBytes` (1 MiB, ceiling 64 MiB) and `maxListValues` (4096, ceiling 7900: `unpack` refuses past 7997 results on Lua 5.1.5, measured), shared by every consumer. `maxOutputBytes` bounds each stage's input and output, inflation included; print input is measured before its whitespace is stripped.
- **`CodecKit.UNBOUNDED`**, one sentinel table kept in the package state so every revision shares it. `SetLimits` accepts it for `maxValues` and `maxStringLength`, which `maxOutputBytes` still bounds, and `GetLimits` returns it; `maxDepth`, `maxOutputBytes` and `maxListValues` refuse it at the caller with the reason. With `maxValues` lifted, the call-time secret scan of `EncodeAsync` stops after `maxOutputBytes + maxDepth + 2` values. API.md's *Limits* table names every limit's default, how to open it and its ceiling. The suite has 103 specs.
- **Asynchronous variants.** `EncodeAsync` and `DecodeAsync` run as one SchedulerKit job on a caller-owned scope and yield when `context:ShouldYield()` says so; a cancelled job never calls back.
- **Allocation.** Work records and fragment arrays are leased from a PoolKit table pool and returned on every path, so calls are re-entrant and encoding a small value again allocates nothing. The asynchronous variants lease nothing.
- **Secret values.** A secret anywhere in a value, and a secret string argument, raise at the caller when the client has `issecretvalue`. Elements are tested with `type` before the probe sees them, and `EncodeAsync` scans the value at the call as far as the encoder would reach.
- **Error levels.** Every programming error (receiver, argument, option, limit, secret, missing SchedulerKit, invalid scope) is reported at the caller's line.
