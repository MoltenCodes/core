# SettingsKit Tests

The SettingsKit suite covers:

- `Open`: the saved variable created with the full layout when missing, adopted when the client loaded it, refused when it is not a table; the same database for a second `Open` of the name (and a refusal for a different schema table or a replaced global); nodes and sealed schemas both accepted, with SettingsKit's own failure table; the "every field optional" rule with the offending path, also inside keyed-section records; malformed schema tables, options and saved-variable names; secret `version`, `migrations` keys and option names refused before they are compared, and omitted options still accepted;
- defaults: scalar and nested record defaults read without being written back, defaults declared inside a table default, a saved record without a default reading its own field defaults, wildcard defaults of a keyed section (records and scalars), a section's own default entries before its wildcard, the first-read copy of an array default, a saved entry of a keyed section declared without a default reading its wildcard and field defaults (through a read, `db:Pairs` and after `Compact`), undeclared fields, views being empty proxies, and a `nil` key of a keyed section reading `nil` after the secret probe was asked;
- validated writes: stored when valid, refused at the writer's line with SchemaKit's failure text, undeclared fields of closed records, nested record fields, whole tables, keyed-section keys, values and entries, the keyed-section bound, `nil` resetting to the default, NaN keys, and `OnChange` with its `(db, scope, key, value, path)` arguments (also not firing for a refused write);
- key rendering: a key holding a `|T...|t` escape and a control byte shown safely in a refusal message and in an `OnChange` path, an identifier key unchanged, and a long key cut between UTF-8 characters;
- secret values: a secret value, a secret nested in a table value, a secret key and a secret read key, each refused at the line that used it with nothing stored; a secret already in the saved table read, iterated and kept by `Compact` as it is stored; a secret stored profile choice skipped by `DeleteProfile`;
- scopes: each of the six scope keys in the saved table, keys resolved once, other characters kept apart, unavailable scopes for each missing identity function (including an empty or secret answer) raising at the reader's line, undeclared scopes, and `OnChange` refused for either;
- profiles: `Default`, `defaultProfile = "char"` (and its fallback), a named default, `SetProfile` with its signal, the recorded choice and the change of `db.profile`, reopening on an earlier session's choice, sorted `GetProfiles`, `CopyProfile`, `ResetProfile`, `DeleteProfile` (current and missing refused, views detached, choices forgotten), name validation, a corrupted stored choice, `ResetDatabase`, and profile methods without a profile schema;
- migrations: a new table stamped without running steps, an older table migrated once in ascending order and not again in the next session, an unversioned table treated as version 0, an older table advanced without a migrations table, a failing step retried next time; each step a transaction: a step that writes and then raises leaving the saved table and its version untouched (scale 1 becomes 2 after the retry, not 4), a failure injected at each step of a three-step migration keeping the earlier steps committed and applying every step once on retry, the saved-variable table keeping its identity while each step receives a copy (and a reference kept past the step reaching nothing saved), shared references and cycles (also through the root) preserved, no metamethod invoked and keys kept as they were, a secret carried over as it is, and 10,000 nested profiles migrated in one step; a layout section that is not a table refused before anything is written, the last step's result refused (and retried) when it leaves one, and an earlier step allowed to pass through one; and a malformed stored version;
- `Compact`: default-equal values removed deeply while changed values, tables without defaults and empty profiles stay, every stored character compacted, compaction on `PLAYER_LOGOUT` through EventKit, a failing logout compaction reported, and a host without EventKit;
- values a saved variable cannot hold: a view assigned as a value (the review's aliasing probe, on a host without `issecretvalue`), a view nested in a table, tables with a metatable;
- keyed-section reads storing nothing: twelve reads of a `max = 3` section with a plain-table wildcard, a key the key schema refuses, and a plain-table default read inside an entry that is not saved;
- `db:Pairs`: record and keyed-section views, undeclared saved keys, no allocation, and refusal of anything but a view of the database;
- `db:Validate`: accepted values with nothing written or signalled, refusal messages identical to a refused write's (schema, undeclared field, key schema, view, metatable, secret value and key), a full keyed section, paths through a non-record, the current profile, argument errors, and no allocation for a valid array-path check;
- a secret read key on a record view, and undeclared keys surviving `Compact`;
- allocation guards (`collectgarbage("count")` with the collector stopped) on a default read and a saved read, top-level, nested and through an entry, on reads that resolve again after `Resync` or a table write, on getter calls, on fast-path writes nobody listens to (top-level, nested, in an entry), on a profile switch with a read, and on a validated write of an existing key with a listener connected;
- the fast paths of revision 6: every candidate value (each type, `-0`, fractions, `2^53`, infinities, NaN, strings for every rule) written to every kind of scalar field (`number` with and without `integer` and bounds, `string` with length, pattern and `oneOf`, `boolean`, a mixed `enum`, and the `custom`, `oneOf` and `any` kinds left to SchemaKit), at the top, in a nested record and in a keyed-section entry, before and after the view took a valid write, with `Validate` and the write both giving SchemaKit's verdict and the same message; SchemaKit's message for a refusal on a verified view; a lowered `maxDepth` refusing a nested write the fast path would otherwise take; an entry whose key the key schema refuses and a full section refused on every attempt; a detached view, a secret value and key, an undeclared field and a table value after verification; read kinds from a record's own default, saved values of every kind, keyed-section scalar and table defaults; two databases sharing one compiled schema kept apart; views built to the `maxDepth` in force at each `Open`; change and profile listeners connected after earlier changes, and a disconnected one; and the shared logout compaction (every database, one failure reported once and isolated, a database opened later, a read-only one skipped);
- duplicate embedded loading, Registry publication, yielding to a newer revision, missing Registry, SchemaKit or SignalKit, an incomplete facade, loading without EventKit, an in-place upgrade to the next revision that keeps the database, its views, its listeners and its logout compaction, the upgrade over revision 2 keeping the facade, state, prototype, limits, database and listeners and applying the secret refusals at once, the upgrade over revision 1 repairing the defaults of entry views revision 1 built below a keyed section without a default, the upgrade over revision 4 giving layout 1 databases the read-only fields (writable as opened, the newer stored version recorded for `ResetDatabase`) and `IsReadOnly`, and the upgrade over revision 5 bringing a database, its scope plan, every node, its eagerly created signals and the package state from revision 5's shapes to revision 6's (reads, full-check and fast-path writes, a stale probe key cleared, listeners connected before the upgrade, `Validate`, the undeclared-scope message, and each database compacted once at logout, the old one by its own listener);
- `error` levels: every `Open` and database-method argument failure, every receiver failure and the view refusals report the caller's own line;
- limits: the default scan bound of 65536 entries, `maxScannedEntries` honoured by writes and `Validate`, `UNBOUNDED` scanning a 70000-entry table, invalid values refused at the caller's line; `maxProfileNameLength` and `pathKeyLimit` enforced by default and raised through `SetLimits`, a raised name limit honoured for a stored choice, `UNBOUNDED` refused with its reason, a secret `maxScannedEntries`, limit key or limit value refused at the caller's line, invalid and unknown limits refused atomically at the caller's line, a fresh `GetLimits` table; and the sentinel, the set limits and a database's scan bound kept across an in-place upgrade;
- newer stored data: opened read-only by default, read and iterated without any write (no layout, profile or profile choice created, a plain-table default not stored), every view write in every scope (nested records, keyed-section entries, `nil`) and every changing method (`SetProfile`, `CopyProfile`, `ResetProfile`, `DeleteProfile`, `ResetDatabase`, `Compact`) refused at the caller's line with nothing stored or signalled, `Validate` answering the refusal, the logout compaction skipped, a non-table section still refused; `allowNewerData` writing without ever lowering the stored version (also through `ResetDatabase`), `IsReadOnly` for current, older and unversioned data, the mode kept by a later `Open`, and the option's validation (type, secret, `version` required, unknown field);
- corrupted data: a record or keyed section stored as a scalar read as its default view (or `nil` without a default), iterated as empty, not overwritten by a read, and replaced by the next write;
- view caches (revision 7): a direct edit of the saved variable shown only after `Resync` (a scalar inside a held table at once), `Resync` on a read-only database, a saved table carrying a metatable read without invoking it; a held view and the views below it never answering from, or writing into, a stale table across every mutation path (table writes, `nil` resets, keyed entries created, replaced and removed, a corrupted scalar replaced, a materialising read, `SetProfile`, `CopyProfile`, `ResetProfile`, `DeleteProfile`, `ResetDatabase`, `Compact`, the logout compaction, a migration); the upgrade over revision 6 keeping detached roots detached;
- getters: the view's answer for every kind of field, writes, resets and structural changes followed, scope getters following `SetProfile` and `ResetDatabase` while view getters stay on their profile, detached views, read-only databases, `Resync`, the key probed when the getter is made and not on cached calls, refusals at the caller's line, a secret saved value returned as it is stored on the dispatched and the fast path (the documented nil-rule exception), and getters made before an in-place upgrade, including by revision 7;
- manifest/runtime API and revision consistency.

`support/SettingsKitTestEnv.lua` loads Registry, SignalKit, EventKit, SchemaKit and SettingsKit in that order. It stubs the player identity (`UnitName`, `GetRealmName`, `UnitClass`, `UnitFactionGroup`) through `SetPlayer`, where a field set to `false` leaves that function out, and removes it again in `Reset`, together with every saved variable a spec named or SettingsKit created; the shared fixture does not model these globals. `InstallSecretProbe` and `NewSecret` provide an `issecretvalue` that reports the spec's own secret tables. EventKit is an optional dependency, so the runner puts it on `LUA_PATH`; `NewPackageWithoutEventKit` simply leaves it out of the module chain.
