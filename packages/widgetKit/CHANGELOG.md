# Changelog

## 0.2.0 — 2026-09-25

Two persistence defects a read-only audit found in position bindings, and the fixes.

- Added: `WidgetKit:BindPosition(frame, storage, options?)` and `Frame:BindPosition(storage, options?)` take, besides a table, a function that returns the storage table; it is called at every save and every `Restore`. A binding made over `db.profile` captured that one view: after `db:SetProfile("Second")` a drag still wrote into `profiles.Default`, and the second profile's anchor was never applied. `function() return db.profile end` follows the current profile, and `docs/API.md` ("SettingsKit profiles") documents connecting `db:OnProfileChanged` (and `OnProfileCopied`) to `binding:Restore()`. WidgetKit still never looks SettingsKit up. Anything else is refused at the caller: `WidgetKit:BindPosition storage must be a table or a function that returns one` (it said `storageTable must be a table`).
- Fixed: a save that fails is reported through the host error handler and never raised. Once the pinned profile was deleted or reset away the view was detached, and the next drag raised from the title bar's `OnDragStop` after the frame had been re-anchored, so the window's `OnMoved` callback never fired. A storage function that raises or returns no table (`WidgetKit.Binding storage function must return a table; it returned a nil`), and a storage that refuses the write or the read, are now reported from `Capture`, from the SchedulerKit debounce, from the `Flush` and `Release` flush and from `Restore`; the frame stays where the user put it, `Capture` returns the anchor and fires `OnMoved`, and `Release` releases.
- Fixed: `Anchor.Apply`, and so `Binding:Restore`, left a frame with no point at all and the saved scale when the client refused the anchor, so a saved anchor naming the frame itself, or a frame anchored to it, hid the window every session with no way to drag it back. A `relativeTo` that is the frame is refused before anything changes, and a `SetPoint` the client refuses (an anchor cycle) is undone: the frame's points and scale, kept in a scratch table borrowed from the layouts' pool, are put back. Both answer `false, "refused"`, a new reason; `Restore` answers `false` and reports nothing. The fixture's frame stub already refused both as the client does.
- Base widget versions: `Frame` goes to version 4, because the window's `BindPosition`, stored on each window by its constructor, now accepts a storage function; the other nine text-bearing types stay at 3 and `ScrollFrame` and `Spacer` at 1.
- Implementation revision 8. No state changed: an in-place upgrade from revision 7 (or earlier) keeps the prototypes, types, pools, live widgets, bindings, renderings and limits; pooled windows are retired at once and borrowed ones on release. Bindings an older copy made run this revision's `Capture`, `Restore`, `Flush` and `Release`; only their SchedulerKit debounce keeps the older copy's save until the binding is made again. A binding this revision makes debounces through the new `dispatch.saveBinding`, so a later revision replaces its save too. No new top-level local: the storage helpers live in a `do` block with `saveBinding` and `Restore`, and the main chunk still peaks at 198 active locals (`luac -p -l -l`, the most locals whose ranges overlap in the main function).
- `docs/API.md`: implementation revision and `REVISION` 8, the storage function, "A failed save is reported, never raised", "SettingsKit profiles", `Anchor.Apply`'s `"refused"`, `Restore`'s outcomes, `Frame` at version 4, the cost of `Apply` and `Restore`, the upgrade and a deviation note; `docs/INTERNALS.md` describes storage resolution, the kept points and the new `dispatch` entry; the README and `docs/EMBEDDING.md` show the profile pattern.
- Specs: new `BindingStorage_spec.lua` (a storage function at every save and restore, a SettingsKit profile switch with `OnProfileChanged`, a drag into a detached view reported without raising and the window left where it was dropped, a raising and an empty storage function, a storage whose write and read raise, the refusal at the caller); `BindingHost_spec.lua` gains a debounced save and a release flush into a detached view and a storage function naming the current profile; `Anchor_spec.lua` the self anchor, the anchor cycle with two points and the scale put back, and an allocation guard on a refused anchor; `Binding_spec.lua` a refused saved anchor on bind; `Bootstrap_spec.lua` an in-place upgrade of a revision 7 copy whose `Frame` was at version 3. 223 specs (210 before).
- The real-client suite: a new anchors test makes the client's own `SetPoint` refuse a frame anchored to itself and an anchor cycle (both messages logged) and expects `Anchor.Apply` to answer `false, "refused"` with the probe's two points and scale unchanged, and a `BindPosition` over such a saved anchor to leave the frame in place and report nothing; the facade test expects `Frame` at version 4. `EXPECTED.md` expects 41 tests (34 passed and 7 skipped on a client without secret values), and its list of frames left for the session now counts the eight probes the tests use (it said two).

## 0.1.7 — 2026-09-25

What the second real-client run of `tests/client/MoltenCodesTest_WidgetKit` on Retail 12.1.0 b69933 (2026-09-25, 11:09, 39 passed, 1 failed) showed, and the fix.

- Fixed: a pooled widget whose text once showed a secret measured every later plain text as a secret. `ClearText` on release made the font string's text plain again but not its measurements (the log: `reused Label: GetText() secret false, GetStringHeight() secret true`), so a reused `Label` fell back to one line (12 pixels) for any text, however long. Every text a text setter may give a secret now shows a secret on a font string of its own, made on that slot's first secret with the same anchors, font, justification, colour and word wrap and kept for the widget's life; a plain text, in the same use or a later one, goes back on the font string (or, for a `Button`, the button) that never held a secret. This covers the `Label`, `Heading` and `Button` texts, the `Frame` and `Group` titles and the `CheckBox`, `Slider`, `EditBox`, `Dropdown` and `ColorPicker` labels. Bounded: at most one extra font string and one small table per text slot, only once a secret is shown, never more however often secrets come back; no widget leaves its pool and nothing counts against the frame cap. A `Button`'s secret text takes the font of the button's own text, again after `SetDisabled`.
- Fixed after the third real-client run (11:30, 39 passed, 1 failed): the secret font string copied its word wrap with `GetWordWrap`, which the client's font strings do not have (`WidgetKit.lua:3239: attempt to call a nil value`). It now reads `CanWordWrap`, the getter every flavour documents, and the fixture's client rule answers `CanWordWrap` in place of the `GetWordWrap` the stub had invented.
- Base widget versions: the ten types above go to version 3; `ScrollFrame` and `Spacer` stay at 1.
- Implementation revision 7. No state changed: an in-place upgrade from revision 6 (or earlier) keeps the prototypes, types, pools, live widgets, bindings, renderings and limits; the ten raised types retire their pooled widgets at once (including any whose font string showed a secret) and their borrowed ones on release. No new top-level local: the private `setShown` helper gave way to the client's own `SetShown`, and the main chunk still peaks at 198 active locals.
- `docs/API.md`: implementation revision and `REVISION` 7, base versions 3, "Secret values" records the measured fact with its date and the secret font strings, "Secret sizes" and "Embedded copies and upgrades" follow; `docs/INTERNALS.md` describes `showText` and its bound.
- Specs: the fixture's client rules keep a font string's measurements secret after `ClearText` (the new measured fact) and answer `GetJustifyH` and `CanWordWrap`. New `SecretTexts_spec.lua`: the next use of a `Label` that showed a secret measures a plain text (the client test's case), a plain text after a secret in the same use, one secret font string per slot over fifty cycles, the style carried both ways, a `Heading`'s lines, a `Button`'s font and a `Group`'s content, and every text slot never showing a plain text on a font string that held a secret. An in-place upgrade of a revision 6 copy retires a pooled `Label` whose font string showed a secret. 210 specs (200 before).
- The real-client suite: the reused-label test now expects the reused label's `GetStringHeight()` to be a plain number, its height to match its text, and the font string that showed the secret to be another one; the facade test expects base versions 3.

## 0.1.6 — 2026-09-25

- Fixed: a `Label` passed the client's measurement of its text to `SetHeight` without asking `issecretvalue`. A font string that once showed a secret keeps a secret aspect after `SetText("")`, so the next use of the same label measured a plain text as a secret, and `SetHeight` raised `Secret values are only allowed during untainted execution for this argument` inside WidgetKit (the first secrets test, and two more that reused that label). A measurement answered as a secret now makes the label one line (12 pixels) high and never reaches a setter; every other size WidgetKit reads was already checked (0.1.5).
- Fixed: releases now call `ClearText` (where the client has it) on every font string a text setter may have given a secret: the `Label` and `Heading` texts, the `Frame` and `Group` titles and the `CheckBox`, `Slider`, `EditBox`, `Dropdown` and `ColorPicker` labels. `SetText("")` alone kept the secret aspect, so the next use would still have answered `GetText` with a secret.
- Changed: `EditBox:SetText` refuses a secret at the caller's line even with `allowSecret` (`WidgetKit EditBox:SetText text must not be a secret value: the client's edit box takes one only from untainted code`): the client's edit box raised on one from addon code. The renderer therefore shows an `input` option whose value is secret as `<secret value>`, disabled, whatever `RenderOptions` `options.allowSecret` says; the option is still validated and now has no effect.
- Fixed: text getters answer `""` for an empty text, as `docs/API.md` promised. The client's font strings and buttons answer `nil` after `Create` and after `SetText(nil)`: `Label`, `Heading` and `Button` `GetText`, `Frame` and `Group` `GetTitle`, and every widget's `GetLabel` returned it. `EditBox:GetText` turns a `nil` into `""` too.
- Fixed: a `Frame` window answered `MEDIUM`, not `DIALOG`, once parented to a `MEDIUM` frame: `SetParent` hands a frame its parent's strata. The window now calls `SetFixedFrameStrata(true)` where the client has it, and sets `DIALOG` again on every `Create`.
- Fixed: a `Label` laid out before it was ever drawn measured its text unwrapped (956 pixels wide and one line high on a 300-pixel content): its font string wrapped at its two anchors, which the client had not resolved yet. The font string now has one anchor and a width of its own: 200 from `Create` on, then what `SetWidth` or a layout gives the label.
- `SetLimits` refuses a secret `maxDropdownEntries` or `maxCreatedCeiling` with the package's secret message (`WidgetKit:SetLimits limits.maxDropdownEntries must not be a secret value`) instead of the range message.
- Base widget versions: `Frame`, `Group`, `Label`, `Button`, `CheckBox`, `Slider`, `EditBox`, `Dropdown`, `ColorPicker` and `Heading` go to version 2, as the versioning rule asks of a revision that changes a base widget's constructor; `ScrollFrame` and `Spacer` stay at 1.
- Implementation revision 6. No state changed: an in-place upgrade from revision 5 (or earlier) keeps the prototypes, types, pools, live widgets, bindings, renderings and limits; the ten raised types retire their pooled widgets at once and their borrowed ones on release, so every later `Create` hands out a widget built by this revision. No new top-level local: the main chunk peaks at 198 active locals (199 before; the renderer's `ALLOW_SECRET_TEXT` is gone).
- `docs/API.md`: the implementation revision and `REVISION` row say 6 (they still said 3); "Secret values" records what the client takes, with the date; "Secret sizes" gains the label's string height; the `Label`, `EditBox` and `Frame` rows, the renderer's `allowSecret`, `SetLimits` and "Embedded copies and upgrades" follow the changes above.
- Specs: the fixture gains the client's rules (`packages/widgetKit/tests/support/WidgetKitClientRules.lua`, installed by every loader): frame and font-string `SetWidth`, `SetHeight`, `SetSize` and `SetPoint`, and `EditBox:SetText`, raise the client's message on a value `issecretvalue` reports secret; an empty font string or button answers `GetText()` with `nil`; a font string keeps a secret aspect until `ClearText`; `SetParent` hands over the parent's strata unless it is fixed. Every spec now runs under them. New `ClientRules_spec.lua` (the rules themselves, the getters, the window strata, the label's wrap width and its secret measurement), secret specs for the label's measurement and the aspect cleared on release, and an in-place upgrade of a revision 5 copy whose ten base types were at version 1. 200 specs (191 before).

## 0.1.5 — 2026-09-24

- Fixed: the built-in layouts no longer compute with a size the client answers as a secret. `GetWidth`, `GetHeight` and `GetSize` carry `SecretWhenAnchoringSecret` and `ConstSecretAccessor` in the Retail 12.1.0 b69933 metadata (`packages/apiKit/metadata/retail`), and arithmetic or a comparison on a secret raises (measured on Retail 12.1.0 b69933). `List`, `Fill` and `Flow` ask `issecretvalue` about every size they read: a secret content width or height sizes no child from it and is reported to `LayoutFinished` as `nil` (`Flow` packs rows against a width of 0), and a secret child width or height counts as 0 in offsets and rows.

A `ScrollFrame` no longer passes a secret viewport width to `SetWidth` (which takes a secret only from untainted code) and counts a secret viewport height as 0 when it computes its scroll range.

## 0.1.4 — 2026-09-24

- Fixed: WidgetKit no longer tests a value it did not create as a boolean (`if`, `and`, `or`, `not`) or compares it with `true` before asking `issecretvalue`. On Retail 12.1.0 b69933 a boolean test on a secret raises inside the Kit ("attempt to perform boolean test on ... a secret boolean value"), like a same-type comparison. `docs/API.md` gains a "Secret booleans" table with the outcome for every such place.
- Refused at the caller, settling the question 0.1.2 left open: a secret `disabled` for every `SetDisabled`, and a secret argument to `SetFullWidth`, `SetFullHeight`, `Frame:SetResizable`, `Frame:SetMovable`, `Button:SetKeyCapture`, `CheckBox:SetTriState`, `Slider:SetIsPercent`, `EditBox:SetMultiLine` and `ColorPicker:SetHasAlpha` (`WidgetKit Slider:SetIsPercent isPercent must not be a secret value`); a secret `options.allowSecret` of a text setter or `RenderOptions`, and a secret `options.restore` of `BindPosition`.
- Anchors: `Anchor.Normalize`, `Anchor.Apply` and `Binding:Restore` default a missing `x` or `y` to 0 without `x or 0`, so a secret offset reaches the existing refusal (`... x must not be a secret value`; `Restore` reports it) instead of raising in the test. `Anchor.Read` returns `nil` when the client answers `GetPoint` with secret values, and `Binding:Capture` returns `nil, "notPositioned"` when `GetRect` does; both are secret while a frame's anchoring is secret.
- Layouts: a secret width or height returned by a layout function is ignored like a non-number, instead of being compared in the NaN test and then refused inside `LayoutFinished`.
- Renderer: a secret `tree:IsDisabled` answer disables the option; a secret `IsHidden` answer or node `hidden` keeps it in view without rebuilding on every refresh; secret `tristate`, `isPercent`, `multiline` and `hasAlpha` hints count as unset; a secret `confirm` asks the default question; a secret `fontSize` gets the default font; a secret `step` reaches `SetSliderValues`, which refuses it; a secret answer from `tree:Validate` or `tree:Set` is a refusal, with a secret message shown as `<secret value>`. The write verdict is taken once, as a plain boolean.
- The inline-refusal colour is one table instead of three locals, to make room under Lua's 200-local limit for the renderer's one new helper. No allocation per call.
- Implementation revision 4. No state changed: an in-place upgrade from revision 3 (or 1 or 2) keeps the prototypes, types, pools, live widgets, bindings, renderings and limits and replaces the methods only; every base widget stays at version 1.
- Specs: new `SecretBooleans_spec.lua` (every refused flag at the caller's line, including a secret `true`; the anchor offsets and a saved anchor with a secret offset; secret `GetPoint` and `GetRect` answers; a secret layout size; the renderer with secret `IsDisabled`, `IsHidden`, hints, `confirm`, `Validate` and `Set` answers). Besides the table stand-in, the spec marks plain values (`true`, numbers) as secret, so each outcome differs from what the unchecked code produced. `Bootstrap_spec.lua` upgrades a revision 3 copy in place. 182 specs.
- `WidgetKit` API generation 1 is unchanged.

## 0.1.3 — 2026-09-24

- Secret values: the source comments on limit validation, `SetRelativeWidth`, `SetUserData`, `GetUserData` and `RegisterType` no longer claim that comparing a secret with anything, `nil` included, raises, or that a raw identity test is safe whatever the other side. They state what was measured on Retail 12.1.0 b69933 (2026-09-24): a secret compared with a value of its own type raises (`==`, `~=`, `<`, `<=` and `rawequal` alike) and a secret used as a table key raises, while a comparison with `nil` or with a value of another type answers without raising. The `type(value) == "nil"` rule stays, as the repository's uniform rule that never compares anything. Comments and documentation only: `luac -s -l` gives the same instruction listing before and after, so the implementation revision is unchanged.

## 0.1.0 — 2026-09-23

- Added WidgetKit API generation 1, implementation revision 1: pooled, versioned widgets on frames WidgetKit creates itself, explicit layouts, a saveable anchor value type with position persistence, and a renderer for OptionsKit trees.
- **Type registry.** `RegisterType(name, constructor, version, options?)` returns `true`, `false, "older"` for a lower version or `false, "current"` for an equal one; a higher version retires every pooled widget of older versions through PoolKit generation stamps, and retires borrowed ones when they are released. `GetTypeVersion`, `Create` (`nil, "unknownType"` / `nil, "exhausted"`), `Release`, `IsWidget`, `SetFocus` / `ClearFocus` / `GetFocus` and `GetStatistics`. One capped PoolKit pool per type: `MAX_CREATED` (256) frames unless a registration asks for up to 4096; an upgrade raises the cap only by what it retires and never past 4096. A constructor result that breaks the author contract is refused at the caller of `Create`.
- **Widget base** (`WidgetKit.Widget`): named callbacks (`SetCallback`, `Fire`; 16 per widget, errors reported, never raised), user data, size requests (`SetFullWidth`, `SetFullHeight`, `SetRelativeWidth`), size, anchor and visibility methods forwarded to the frame, `SetParent`, `SetDisabled` (argument check only; types that can be disabled define their own), `IsReleasing` (ancestor-aware), `GetType`, `GetFrame`, `GetParentContainer` and `Release`. The release contract: renderings drawn into a container first, the `OnRelease` callback, children last first, the type hook, then callbacks, user data, size requests and anchors cleared, the frame hidden and re-parented.
- **Container base** (`WidgetKit.Container`): `AddChild` (with `beforeWidget`), `AddChildren`, `ReleaseChildren`, `GetChildren`, `SetLayout`, `PauseLayout` / `ResumeLayout`, `PerformLayout` and the upward `LayoutFinished` report. Layout is explicit, never a reaction to `OnSizeChanged`; a pass inside a pass of the same container, from its layout or from its `OnLayoutStart` hook, returns `false, "recursion"`, and nesting past 32 returns `false, "depth"`. `MAX_CHILDREN` is 256.
- **Layouts** `List`, `Fill` and `Flow`, plus `RegisterLayout` / `GetLayout`; layouts borrow a scratch table from a PoolKit table pool. A content frame with a negative size counts as zero, and `Flow` keeps children whose relative widths fill a row exactly on that row.
- **Base widgets** `Frame`, `Group`, `ScrollFrame`, `Label`, `Button` (with key capture), `CheckBox` (with a third state), `Slider`, `EditBox` (single and multi-line), `Dropdown`, `ColorPicker`, `Heading` and `Spacer`, each at version 1, each with a LuaCATS class. Dropdown lists sit on `UIParent` at `FULLSCREEN_DIALOG` and close on an outside click through one session-wide catcher frame; `SetList` checks every entry before changing anything. `ColorPicker` opens the client picker through `SetupColorPickerAndShow`, its callbacks are disarmed by a release, and the stored alpha is kept without `SetHasAlpha(true)`. A `Frame` starts every use at scale 1, whatever scale a restored anchor applied.
- **Anchors and bindings.** `WidgetKit.Anchor` (`FromRect`, `Normalize`, `Apply`, `Read`, `POINTS`; `Apply` and bindings leave a frame `IsForbidden` or `CanBeAccessedInContext` refuses alone), and `BindPosition` with bindings (`Capture`, `Restore`, `Flush`, `OnMoved`, `Release`, `IsReleased`) that save a fresh plain anchor table into any storage table, a SettingsKit scope view included, debounced through SchedulerKit when it is registered.
- **Renderer.** `RenderOptions(tree, container, options?)` renders every OptionsKit kind with `Validate`-then-`Set` writes, inline refusals, `OnChange` refreshes and a rendering handle (`Refresh`, `Rebuild`, `Release`, `IsReleased`, `GetWidget`, `GetMessage`). A rendering is released with its container and remembers the acquire serial of every widget it took, so a widget re-acquired elsewhere is never touched; a raising `Validate` or `Set` is shown and reported; a failed build releases what it made and restores the container's pause state; an armed `execute` confirmation (`options.confirmText`) disarms after 5 seconds, or at the next `Refresh` without SchedulerKit. `CreateMediaPicker(mediaType)` builds a `Dropdown` over MediaKit's names.
- **Secret values.** Text setters refuse a secret unless `options.allowSecret` is `true`; values a widget would compare, counts and indices included, are refused when secret; released widgets clear their text.
- **Limits.** `WidgetKit.UNBOUNDED`, one sentinel table kept in the package state so every revision shares it; `SetLimits` / `GetLimits` over `maxCreatedCeiling` (4096, an integer from 256 to 16384, `UNBOUNDED` refused because frames are never freed) and `maxDropdownEntries` (1024, `UNBOUNDED` allowed: the dropdown keeps a fixed set of row frames, so an entry is only the consumer's key and label), shared by every consumer and kept across an upgrade; a `maxCallbacks` registration option (16) and `container:SetMaxChildren` / `GetMaxChildren` (256, reset on release), both accepting `UNBOUNDED`. The layout depth of 32 stays a hard ceiling. API.md gains a *Limits* section naming every limit, its default and how to open it.
- The shared test fixture's `FrameStub` models sizes, anchors, regions and the frame types widgets use.
- 151 specs, including allocation guards on acquire/release cycles, `PerformLayout` and `Fire`, in-place upgrade specs, and limit specs for every opened bound, the refusals at the caller's line and the sentinel and limits carried across an upgrade.
