# Changelog

## 0.1.0 — 2026-09-23

First release: CommandKit API generation 1, implementation revision 1. Requires Registry API 2 and SchemaKit API 1; OptionsKit, LocaleKit and ClientKit API 1 are optional dependencies found through `Registry:Find`.

- **Scopes.** `CommandKit:CreateScope()`, `CommandKit:ForAddon(addonName)` and `CommandKit:CloseAddonScopes(addonName)`, on the HookKit and EventKit scope model; `CloseAddonScopes` records nothing for an addon without a scope and returns `false`. A scope holds at most `CommandKit.MAX_COMMANDS` (64) commands, beyond which `Register` returns `nil, "full"`.
- **Registration.** `scope:Register(name, spec)` with `handler`, `arguments` (a `SchemaKit.array` schema or a list of up to 16 per-position schemas), `usage`, `description`, `subcommands` (at most `CommandKit.MAX_DEPTH`, 3, levels and 64 per level) and `complete`. Every spec problem raises at the caller's line, including `arguments` without a `handler`. Registration writes `SlashCmdList[<key>]` and `SLASH_<key>1` through `rawset` with the key `MOLTENCODES_<ADDON>_<NAME>` (`MOLTENCODES_<NAME>` for a manual scope).
- **Collision checks, best effort.** `nil, "taken"` when another scope or addon already uses the slash name (the `SLASH_<key><n>` globals of every foreign `SlashCmdList` and `SecureCmdList` key) or a chat type does (`ChatTypeInfo`), and `nil, "emote"` when an emote does (`EMOTE<n>_CMD<m>` up to `MAXEMOTEINDEX` or 1024). Every global is read by constructed name, and a secret value among them is skipped.
- **Inert globals.** A slash name keeps its key and one permanent dispatcher for the session; `Unregister`, `Close` and `CloseAddonScopes` leave the globals in place doing nothing, and a later registration of the name by any scope reuses them. The API documentation explains how the client's cached slash function can hide a later foreign registration of the name, and how to take it back.
- **Parsing.** `CommandKit:Parse(text)` (allocating) and `CommandKit:ParseInto(text, array)` (allocation-free for text seen before): whitespace runs; `"double"` and `'single'` quotes with `\"`, `\'` and `\\` escapes; a single quote that does not close before a boundary read as an apostrophe; adjacent segments joined into one token; `|H…|h…|h` hyperlinks, `|c…|r` colour-wrapped text (grouped only when its `|r` comes before the next `|c`), `|T…|t` textures and `||` kept whole; any other pipe is one ordinary byte. An unterminated double quote or hyperlink returns `nil, reason`.
- **Dispatch.** Sub-commands are matched without case; tokens are converted for number and boolean schemas, checked with `Check`, and a missing `optional` position receives its declared default; a refusal prints the SchemaKit failure and the generated usage. The handler runs under `pcall`, and a failure is written to the sink and handed to the host error handler. A dispatch of text seen before allocates nothing; nested dispatches are bounded at 4.
- **Context.** `Print`, `Printf` (through `LocaleKit:Format` when LocaleKit is registered), `Usage`, `Fail`, `GetCommandPath` and `GetRawText`; `Print` and `Printf` refuse secret arguments, and a context refuses use after its command returned.
- **Sinks.** `scope:SetSink(sink)` for anything with `AddMessage`, `DEFAULT_CHAT_FRAME` by default, and `CommandKit:CaptureSink()` for tests, keeping the latest 256 lines.
- **Options binding.** `scope:BindOptions(tree, commandName, options)`: `get`, `set`, `reset`, `list` and `exec` sub-commands over an OptionsKit tree, with values parsed per option kind, `validate` messages printed, hidden options treated as unknown, disabled options refused, `confirm` honoured with an explicit `confirm` word, and a secret value shown as `(secret value)`.
- **Completion.** `scope:EnableCompletion()` and `scope:DisableCompletion()`: tab completion of sub-command names, `complete` candidates (secret ones skipped) and bound option paths through a `ChatEdit_CustomTabPressed` replacement that forwards everything else to the function it replaced, and is removed again when the last scope disables completion unless another addon has replaced it since.
- 102 specs, including allocation guards on `ParseInto`, on a checked sub-command dispatch and on an inert dispatcher, and an in-place upgrade spec.
