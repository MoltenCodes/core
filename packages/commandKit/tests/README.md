# CommandKit Tests

The CommandKit suite covers:

- `Parse_spec.lua`, parsing: whitespace runs, double and single quotes, the empty quoted token, escaped quotes (other backslashes kept), a hyperlink with spaces as one token, an item link as the only argument and among others, colour-wrapped text (and a colour without `|r` as ordinary text), textures and `||`, a hyperlink containing a quote inside a quoted token, single quotes read as apostrophes when they do not close before a boundary, adjacent segments joined, `\\` unescaped, an unclosed colour not swallowing text up to another colour's `|r`, a pipe that starts no escape sequence read as one ordinary byte (before whitespace and before a closing quote), unterminated double quotes and links refused with their reason, `ParseInto` filling an array, clearing leftover slots and emptying it on a refusal, `Parse` returning a new array per call, non-string input, and a list of lines answered exactly as revision 6's byte-by-byte parser answered them (tokens or the refusal, through `Parse` and `ParseInto`);
- `Register_spec.lua`, registration: the two globals and the key for addon and manual scopes, a slash name taken by another addon (also through a second `SLASH_<key><n>` and through `SecureCmdList`) or another scope, a chat type's and an emote's slash name (and `MAXEMOTEINDEX` bounding the emote check), a second registration in one scope, the default `maxCommands` and `"full"`, `Unregister` leaving an inert dispatcher and a later registration by another scope reusing the key, malformed names and specs (`arguments` without a handler included), the three-level depth bound, a host without `SlashCmdList`, and Retail 12.1's hashed command lists (modelled by `ImportListsToHash`): a client slash command, a chat type and a secure command refused after the lists are wiped, a secure command only `IsSecureCmd` names, an emote only `hash_EmoteTokenList` holds, CommandKit's own hashed command free again once unregistered, a foreign `hash_SlashCmdList` handler, and secret hash entries and a secret `IsSecureCmd` answer skipped;
- `TakenCheck_spec.lua`, the taken check's caches: the emote index refusing exactly what a full reading of 600 client-like emote indexes (with gaps and mixed case) finds, read again when `MAXEMOTEINDEX`, `maxEmotes` or the `issecretvalue` probe changes, keeping nothing from a reading that met a secret, an emote global written after the first reading not seen until then, `hash_EmoteTokenList` asked on every check; foreign aliases read live (a second alias, a changed alias, a later key and a later chat type), compared without case and by length; and an allocation guard on `Register` and `Unregister` with 50 foreign commands and 600 emotes;
- `Dispatch_spec.lua`, dispatch: every token passed to the handler with the command path and raw text, sub-commands three levels deep matched without case, generated usage and the unknown sub-command message, token conversion for number and boolean schemas, per-position refusals printing the SchemaKit failure and the usage (also for a missing argument and too many), the default of a missing `optional` position filled in, a fresh copy of a table default on every dispatch, no filled default left behind for the next command at that depth, an array schema, an unterminated quote, a handler error isolated and reported to the sink and the host, the context methods, a context kept after its command refused, nested commands with their own contexts, the nesting bound, and `Printf` through LocaleKit's indexed specifiers;
- `Sink_spec.lua`, sinks: `DEFAULT_CHAT_FRAME` by default, `SetSink` and `SetSink(nil)`, `print` without a chat frame, `CaptureSink` copies, `Clear` and its default 256-line bound, and a sink without `AddMessage`;
- `BindOptions_spec.lua`, `BindOptions` against a real OptionsKit tree bound to a SettingsKit-shaped database: generated usage, `get` of every kind, `set` of every kind (toggle words, a number, a select by key and by label, a colour in both forms, multiselect entries, joined input), a `validate` refusal message with nothing written, schema and parse refusals, `reset` to the default and refused without one, `list` of the root, a group and single options, the text of a `desc` function, a raising `desc` function reported as a handler failure, an empty `validate` message replaced, only the named option described (its callbacks run, the others' do not; `list` of the root describes the group), the whole tree described through an OptionsKit without `DescribeOption`, `exec` with and without confirmation, unknown, hidden and disabled options, a missing path, a tree that is not a tree, and a host without OptionsKit;
- `Completion_spec.lua`, completion with a stubbed `ChatEdit_CustomTabPressed`: off until enabled, a unique sub-command, the common prefix and the candidate list, a custom `complete` function by position, bound option paths, forwarding of foreign text, `ChatEdit_GetActiveWindow` when no edit box is passed, restoring the previous function when the last scope disables completion, staying in a chain another addon built on top, a failing `complete` function, and a host without the extension point;
- `Scope_spec.lua`, scopes: `ForAddon` canonical, `Close` leaving an inert global with no output or error, terminal `Close` refusing registration and completion, `CloseAddonScopes` freeing the names and recording nothing for an addon without a scope, and dotted facade calls;
- `SecretValues_spec.lua`, secret values: `Print` and `Printf` (template included) refusing a secret at the handler, secret text and names refused, the client's probe asked and ClientKit never looked up (revision 12), secret completion candidates and secret `SLASH_<key><n>` and `EMOTE<n>_CMD<m>` values skipped, a secret option value shown as a placeholder, a secret `desc` text and secrets inside `color` and `multiselect` values shown as placeholders, a secret sub-command key refused before the keys are sorted, a receiver with a secret `__metatable` and a tree with a secret `__index` refused by type, secret limits refused at the caller, `toggle` over a secret value answered with a message, a secret cursor position leaving Tab to the client, and a secret `confirm` (asking) and a secret `tristate` (read as absent) on a bound tree;
- `Allocation_spec.lua`, allocation guards (`collectgarbage("count")` with the collector stopped) on `ParseInto` of a line with quotes and an item link, on a checked two-level sub-command dispatch and on an inert dispatcher, and a check that the argument of a command without sub-commands is never lower-cased;
- `Limits_spec.lua`, limits: `maxCommands`, `maxSubcommands`, `maxPositions` and `maxSlashAliases` enforced at their defaults, honoured as scope options and lifted by `UNBOUNDED`; invalid and unknown options refused at the caller; a table option or limit key named by its type without running its `__tostring`; `ForAddon` options applied on creation and a conflicting later value refused; `GetLimits` defaults in a fresh table; `maxCaptured` set and lifted; `maxCompletions` and `maxEmotes` set, capped at their ceilings and refusing `UNBOUNDED` with their reasons; invalid `SetLimits` tables refused at the caller with nothing changed; and an upgrade to the next revision keeping the sentinel, the set limits and a scope's limits;
- `LogoutClose_spec.lua`, closing addon scopes at logout: a LifecycleKit that names `commandKit` in `CLOSES_ADDON_SCOPES` left to close the scope after the shutdown callbacks (also for an addon without its own LifecycleKit instance), an older LifecycleKit's `OnShutdown` subscription (made once, disconnected by an early `CloseAddonScopes` or `Close`, and also used for a list that does not name `commandKit`), the one `PLAYER_LOGOUT` watcher through EventKit, nothing arranged without either, the decision taken again when LifecycleKit loads later, a failure in another Kit reported, the upgrade of a revision-1 scope layout, and the subscription and watcher kept across an upgrade;
- `Bootstrap_spec.lua`, duplicate embedded loading, Registry publication (with `UNBOUNDED`, `SetLimits` and `GetLimits`), loading with Registry alone (no SchemaKit, revision 12), yielding to a newer revision, a missing Registry, an incomplete facade, an in-place upgrade to the next revision that keeps commands, inert dispatchers and the completion replacement working, an upgrade that keeps the `UNBOUNDED` sentinel and the set limits, the in-place upgrades from revisions 2, 3, 4, 5, 6, 7, 8 and 9 (facade, prototypes, package state and scope kept; a secret limit refused after the upgrade from 3; a secret `confirm` flag asking for confirmation after the upgrade from 4; a client command found in Retail 12.1's lookup tables refused, and the upgraded copy's own hashed command still its own, after the upgrade from 5; the emote and taken checks working with fresh caches after the upgrade from 6; options checked as revision 8 checks them after the upgrade from 7; table option and limit keys named by their type after the upgrade from 8; the client's probe asked after the upgrade from 9; `SetLimits` messages of the shared `limits` block), and a facade whose `UNBOUNDED` disagrees with its state refused;
- `Parts_spec.lua`, the core and its parts (revision 11; the Arguments part from revision 12): every part method raising at the caller with the file to embed while its part is missing, registration and `Close` working without the parts, a part loaded after the core and the core loaded again after the part, a newer part revision replacing the methods and an equal or older one changing nothing, a part refusing to load before its core, and the upgrade from revision 10 keeping a bound command and enabled completion (the revision-10 tab function kept, the part methods naming their files, `Close` counting completion off);
- `ScopeExtras_spec.lua`, revision 11's core additions: `scope:GetCommands` and `CommandKit:GetCommands` sorted and fresh, the prefix on handler output, usage and refusals, `scope:Print`/`Printf` outside a handler, `Dispatch` (ran, unknown name, another scope's name, a raising handler reported, argument and closed-scope refusals), and `Reopen` (a manual scope reopened empty with its sink and prefix, an addon scope refused);
- `PathSyntax_spec.lua`, the `syntax = "path"` binding: setting and reading by group and key without case, a dotted path as one word, toggles flipped and set, a group listed, `onEmpty` and the root listing, a button with its confirmation, unknown, hidden and disabled options, the verbs kept (a root option named like a verb), `GetBoundTree` until `Unregister`, the path index built once per binding and dropped by `OnStructureChanged`, completion of keys and values, option refusals, and `onEmpty` with the verbs;
- `Providers_spec.lua`, completion providers: a pattern matched against the text before the word, an empty pattern, the common prefix and the listing (with the scope's prefix), providers merged in order with a raising one reported, a scope's own commands completed first, `"taken"`, `"full"` and `maxCompletionProviders`, the chain uninstalled after the last provider and on `Close`, a cursor not at the end, a host without the hook (`"unavailable"`), and argument refusals;
- `ArgumentsPart_spec.lua`, the Arguments part (revision 12): the core alone (Registry only) registering and running plain commands, sub-commands and usage; `arguments` refused at the caller with the file to embed, at the top level and in a sub-command; the part refusing to load without SchemaKit and over a core older than revision 12; the Options part refusing to load without it; the helpers it publishes for the Options part; an Options part of revision 1 (a byte copy, `fixtures/CommandKit-Options-revision1.lua`) working with it; and the in-place upgrade from revision 11 (a byte copy, `fixtures/CommandKit-revision11.lua`): a command with arguments registered before it keeps dispatching without the part, a `Register` with arguments handed to revision 11, the hand-over dropped once the part loads, and none kept when the part loaded first;
- `ErrorLevels_spec.lua`, `error` levels: facade, scope and context argument failures and spec refusals several sub-commands deep all report the caller's own line;
- `Manifest_spec.lua`, manifest/runtime API and revision consistency.

The shared fixture does not model the chat host, so `support/CommandKitTestEnv.lua` installs `SlashCmdList`, a `DEFAULT_CHAT_FRAME` whose lines `ChatLines` returns, a counting `ChatEdit_CustomTabPressed` and `ChatEdit_GetActiveWindow`, a `ChatTypeInfo` with `SAY` (`/s`, `/say`) and `GUILD` (`/g`, `/guild`), and the emotes `/dance` and `/wave` (`/greet`) as `EMOTE<n>_CMD<m>`, and removes them again in `Reset` together with every `SLASH_*` and `EMOTE*_CMD*` global. `ImportListsToHash(secureCommands)` does what Retail 12.1's chat frame does at load and before each typed line: it moves `SlashCmdList`, `ChatTypeInfo` and a private secure list into `hash_SlashCmdList`, `hash_ChatTypeInfoList` and `hash_EmoteTokenList`, leaves the entries behind an `__index` proxy, wipes the lists, removes `SecureCmdList` and installs `IsSecureCmd`. `RunSlash(line)` does what the client does with a typed line: it finds the key whose `SLASH_<key><n>` matches and calls the slash function with the rest of the line. `NewEditBox` and `PressTab` drive completion.

SchemaKit (the Arguments part's) and OptionsKit (the Options part's) are part dependencies, and LocaleKit, EventKit and LifecycleKit are declared under `optionalDependencies`, so the runner puts them on `LUA_PATH`. `LoadEventKit` and `LoadLifecycleKit` add the last two after CommandKit, and `SetClosesAddonScopes` writes `LifecycleKit.CLOSES_ADDON_SCOPES` onto the loaded facade with `rawset`, or removes it to model a LifecycleKit older than 0.6.0. `NewPackage` loads Registry, SignalKit, SchemaKit, OptionsKit (and its Bind part when OptionsKit has one), CommandKit and its three parts; `NewPackageWithoutParts` stops before the parts; `NewPackageWithLocaleKit` adds LocaleKit to `NewPackage`; `NewPackageAlone` loads Registry and CommandKit's core only; `NewRevision11Package` loads the revision-11 byte copy over Registry, SignalKit, SchemaKit and OptionsKit. `LoadPartRevision(part, revision)` runs a part's source as another part revision. The `BindOptions` specs register a SettingsKit API 1 stand-in and a SettingsKit-shaped database so bound options and `Reset` can be exercised.
